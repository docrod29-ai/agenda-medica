# 8. NEXUSMED DESIGN CONSTITUTION

1. Clinical information beats decoration.
2. Patient identity and current encounter context dominate hierarchy.
3. One primary action per visual region.
4. Progressive disclosure beats information dumping.
5. AI appears contextually, not as a generic chatbot everywhere.
6. Color communicates meaning, action or brand—not decoration.
7. Motion communicates causality, state or continuity—not spectacle.
8. Spacing establishes hierarchy before borders do.
9. Borders are used only when structure requires them.
10. Avoid decorative gradients.
11. Avoid excessive pills, chips, badges, shadows, glass effects and floating cards.
12. Avoid card grids when a list, timeline, canvas or structured surface communicates better.
13. Avoid rounded-everything syndrome.
14. Avoid generic AI sparkle iconography as the primary identity.
15. Avoid giant hero sections inside clinical workflows.
16. Avoid sidebars that become feature warehouses.
17. Avoid modal overload.
18. Avoid popups for low-risk information.
19. Avoid visual competition between clinical facts and administrative controls.
20. Avoid full-page reload mental resets.
21. Preserve exact clinician context across navigation.
22. Use whitespace deliberately.
23. Dense information is acceptable when structured and clinically useful.
24. Desktop workflows are keyboard-capable.
25. Mobile workflows are touch-native.
26. Critical actions require obvious confirmation and recovery.
27. Empty states teach the next useful action.
28. Loading states preserve layout and context.
29. Error states explain recovery.
30. Signed/released/draft clinical states are visually unambiguous.
31. AI confidence and provenance are inspectable when clinically relevant.
32. No screen should look like a component-demo page.
33. No page should feel visually unrelated to another NexusMED page.
34. The design system reduces decisions, not creates bureaucracy.
35. A clinician should understand screen hierarchy within roughly two seconds.
36. A first-time physician should complete the golden flow with minimal training.
37. The UI remains useful if AI is unavailable.
38. Accessibility is part of quality.
39. Responsive design is not desktop shrunk onto mobile.
40. If a component looks generically AI-generated, redesign it.

# 24. TYPOGRAPHY / COLOR / SPACING / MATERIAL

Create semantic typography tokens and a limited weight set. Establish hierarchy through size, weight, spacing and placement before color.

Create semantic color tokens for canvas, surface, text, brand, success, warning, danger, information, selection, focus, disabled and borders. Use a predominantly neutral environment. Never rely on color alone.

Create consistent spacing and layout scales, content widths, dense clinical widths, panel widths, safe touch spacing and mobile insets.

Use few radius/border/shadow values. Shadows are rare and indicate real layering. Do not decorate every panel with elevation.

---

# 25. MOTION AND MICROINTERACTIONS

Motion serves cognition: state change, continuity, causality, confirmation and orientation.

Create named motion tokens for quick feedback, standard transition, panel enter/exit, list insertion, modal/sheet, route/context transition and streaming state.

Respect reduced motion. Do not animate critical numbers or warnings distractingly.

Design feedback for save, autosave, recording, streaming, copy, sign, task closure, medication change, result review, appointment move, undo and error recovery.

---

# 26. FORMS / EMPTY / LOADING / ERRORS

Forms: visible labels, field-specific errors, clear required state, keyboard order, constrained numeric fields, units bound to values, robust date/time, safe autocomplete and progressive disclosure.

Empty states answer what this is, why it is empty and what to do next.

Loading preserves layout/context; never erase the whole screen during ordinary refetch.

Errors explain what failed, what was preserved, what can be done, whether retry is safe and whether support is needed. Never silently lose drafts.

---

# 27. RESPONSIVE + ACCESSIBILITY

Create intentional desktop, tablet and mobile experiences. Do not stack desktop cards vertically and call it mobile.

Critical workflows must have explicit mobile designs.

Require keyboard navigation, visible focus, logical order, semantic HTML, labels, screen-reader names, contrast, non-color status, reduced motion, touch targets, zoom resilience and dynamic-text resilience where applicable.

Critical accessibility failures that prevent safe use are release blockers.

---

# 28. CONTENT DESIGN + INTERNATIONALIZATION

Use verbs for actions and nouns for destinations.

Layouts must tolerate Spanish, English, longer translations, accents, medical abbreviations and localized numbers/dates/times.
